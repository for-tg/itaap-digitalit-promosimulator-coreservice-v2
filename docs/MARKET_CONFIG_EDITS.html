Verification

New code + old pickle reproduces the baseline exactly. The full API response set — three years of historical KPIs in both economics modes, the SKU and region lists, a retro run and a plan run — serialises to 2,729,429 bytes with SHA-256 478d0d683183b9cc51f7efd7, byte-identical to the reference. A structural comparison reports 0 differing leaves across roughly 41,000 numbers.

New code + new pickle runs clean. All 40 API operations return without a single 5xx, and the market values in force come from meta, not the code defaults.

How it works

One mechanism, applied once at load. Every market-specific constant in the engine is now a default; _apply_market_meta() overwrites the ones the artifact declares, and init_engine() calls it before anything reads them.

app/engine/promo_engine.py:280
        # Market values come from the artifact before anything reads them.
        _apply_market_meta(data.get("meta"))

An artifact without a meta block changes nothing — every default is the value that was hardcoded before. That is what makes exact baseline parity possible while the same code serves a new market from its own declaration.

Why constants had to stop being imported by name

Several modules did from app.engine.promo_engine import DISCOUNT_GRID_ALL. That binds the value at import, long before any pickle is read, so rebinding it at load time would never reach the caller. Those imports were changed to module attribute access (promo_engine.DISCOUNT_GRID_ALL) so the market's value is the one actually used.

The base-volume shift is the new artifact's own data fix — the old pickle rounded base quantity to whole units and stored a log that disagreed with it on 62% of rows. Revenue, profit and spend are computed from actuals and are unchanged to the last decimal, which is what makes the comparison trustworthy.
